# BOQ_AI

AI-assisted BOQ estimation and tender costing platform for Fire Protection and
MEP workflows.

BOQ_AI imports BOQ workbooks, matches line items against a master database,
calculates deterministic costs, supports expert review and approval, and exports
internal/client Excel outputs.

## Runtime

- Settings: `config.settings`
- Database: PostgreSQL database `boq_db`, user `boq_user`
- Server: Ubuntu EC2, `13.205.90.58`, Mumbai `ap-south-1`
- Web stack: Nginx, Gunicorn, Django
- Jobs: Celery + Redis
- Email: optional; blank SMTP settings use console logging

Keep real secrets only in `/srv/boq_ai/.env` on the server. Never commit PEM
files, database passwords, API keys, or SMTP credentials.

Local development also uses PostgreSQL. Use the same database name and user on
your machine, with `DATABASE_URL` pointing to `localhost`. When deployed to EC2,
`localhost` points to PostgreSQL installed on that EC2 server.

## Local Development Quick Start

> **Required Python:** 3.14.5 (see `.python-version`)

**1. Clone and create the virtual environment**
```bash
git clone <repo-url>
cd BOQ_AI
python3 -m venv .venv
.venv/bin/pip install -U pip
.venv/bin/pip install -r requirements.txt
```

**2. Create local PostgreSQL role and database**
```sql
CREATE USER boq_user WITH PASSWORD 'replace-with-your-local-password' CREATEDB;
CREATE DATABASE boq_db OWNER boq_user;
GRANT ALL PRIVILEGES ON DATABASE boq_db TO boq_user;
```

**3. Configure your local `.env`**
```bash
cp .env.example .env
# Edit .env and set:
#   DATABASE_URL=postgres://boq_user:replace-with-your-local-password@localhost:5432/boq_db
#   SECRET_KEY=<any-local-value>
#   DEBUG=False
#   DJANGO_SETTINGS_MODULE=config.settings
```

**4. Run migrations and create a superuser**
```bash
cd backend
../.venv/bin/python manage.py migrate
../.venv/bin/python manage.py createsuperuser
```

**5. Start the development server**
```bash
../.venv/bin/python manage.py runserver
```

**6. Run tests**
```bash
../.venv/bin/python manage.py test tests --no-input
```

> For full production server setup (Gunicorn, Nginx, Celery, Redis),
> see `docs/RUN.md` and `docs/DEPLOY.md`.

## Install (Production)

```bash
cd /srv/boq_ai
python3 -m venv .venv
.venv/bin/pip install -U pip
.venv/bin/pip install -r requirements.txt
```

Then configure `/srv/boq_ai/.env`, run migrations, collect static files, and
start Gunicorn/Celery through systemd. See `docs/RUN.md` and `docs/DEPLOY.md`.

## Security

Generate a fresh `SECRET_KEY` on the server:

```bash
/srv/boq_ai/.venv/bin/python -c "from django.core.management.utils import get_random_secret_key as g; print(g())"
```

Use it in `/srv/boq_ai/.env`:

```ini
SECRET_KEY=paste-generated-value-here
ALLOWED_HOSTS=13.205.90.58
```

`SECRET_KEY` cannot be removed. Django uses it to sign sessions, CSRF tokens,
password reset links, and other trusted data. If it is missing or leaked, the
app is not production safe.
