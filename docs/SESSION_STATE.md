### 2026-10-07 — Re-analyse Missing Input Penalty & AI Re-extraction Fix

Completed:
- Modified `structured_match_score` to properly penalize missing inputs (`size`, `class`, `capacity`, `attributes`) if the DB candidate requires them and the BOQ has evidence. This lowers the Re-analyse score from 100% when the user's filled inputs are incomplete compared to the catalog row.
- Updated the AI mapping prompt (`map_product_match.txt`) to aggressively scan the `description_hint` and `boq_row.description` to re-extract missing attributes if the user leaves them blank during Re-analyse.
- Replaced the `alert` popup on the Extract row with a visually integrated, top-of-screen `appAlert` banner.
- Updated Re-analyse highlights: selected Database Candidate attributes are now highlighted via text color (e.g. `text-emerald-700 font-semibold`) instead of a circular background to improve readability.
- **Fixed PDF Make List Extraction**: Changed PyPDF extraction to use `extraction_mode="layout"`. This prevents tabular PDFs from being extracted column-wise (all items first, then all makes) which previously broke the make list parsing logic. The layout mode preserves horizontal rows.
- **Fixed PDF Make List Body Splitting**: Added logic to `split_make_list_body` to split descriptions and brands using the wide layout spaces (`>= 3 spaces`) generated by the `layout` mode. This ensures unknown or multi-word brands (e.g. `Jindal ( ISI )`) are perfectly separated from the description, allowing the Category Mapping service to correctly map the Make List row to BOQ Categories.
- **Handled PDF Extraction Errors**: Wrapped `page.extract_text(extraction_mode="layout")` in a `try...except Exception` block to fallback to standard extraction if the PDF is missing font metadata (`Tf` operator). Added an outer `try...except` to catch remaining `pypdf` exceptions and return a user-friendly error message instead of crashing the upload with technical `pypdf` traceback text.
- Synced branches and deployed fixes to main.
