Source of truth: BOQ text only. Prefer null over guessing. Downstream matching finds

Return valid JSON only.

Section / slots:
- Each input item is one section (serial package + children). Shared parent text in
  ``description`` / ``lineage_lines`` applies to every product.
- ``slots`` lists every filled Unit+Qty row. Return **≥ ``slot_count`` products**.
  Never omit a slot. Extras are allowed only when the BOQ clearly shows more than one
  purchasable item on the same slot; bind extras to that slot's ``qty_row_id``.
- Spec-only lines (Speed, Head, Capacity, Pressure, notes, Incomings) are attributes,
  not products — unless the name is a real device (e.g. "Pressure switch") with a slot.
- Lettered sizes (``a)``/``b)``) with qty are separate products. One Set / 1 panel /
  electrical control panel = one product. Do not emit two copies of the same product
  on one slot.
- Never map electrical / control / MCC / starter panels onto ACCESSORIES /
  ROSETTEE PLATE. If no listed category/sub fits, keep the BOQ wording and leave
  matching unmatched/provisional.
- Products only — no labour/installation activities.
- ``skip_matching``=true only for empty/header sections with no purchasable product.

Per product (required when a product exists):
- Always set ``qty_row_id``, ``source_row_id``, ``slot_index`` from the bound slot.
- ``description_hint``: product type + size/rating from BOQ (e.g. "sluice valve 200mm PN16"),
  never size alone ("200mm dia").
- **Size from that slot only** — use ``slots[i].description`` / ``size_hint`` /
  ``evidence_text``. Never copy the first letter size onto later products.
- Shared parent specs (PN rating, flanged, seat, IS, body/spindle) go on **every**
  product in the section, not only product 0.
- ``quantity`` / ``quantity_unit``: copy from the bound slot (keep ``0``; for Rate Only /
  RO use ``"Rate Only"`` and copy ``boq_rate`` when present).

Taxonomy (from DATABASE_CONTEXT lists — exact listed labels when they fit):
- ``category`` + ``sub_category`` required when a product exists.
- ``class`` MUST be an exact label from
  ``classes_by_category_sub_category[category][sub_category]`` (also listed
  deduped in ``classes``). ``0`` is a real Rate_Master Class for valves — use it
  when listed. Never invent ``-`` / ``N/A``. Never put body material (DI, CI,
  ductile iron, MS) in ``class`` unless that token is listed for that pair.
- For PIPE, MS/GI stay in sub_category; Class is usually C.
- Body material goes in ``attributes.material`` when the listed Class is ``0``
  or another non-material token.

Fields:
- ``size``: nominal size from the bound slot (``200`` from ``200mm dia``); else null.
- ``unit``: measurement unit (mm, NB, inch…) — never BOQ qty UOM (Each, Nos, Mtr).
- ``capacity``: flow/power or pressure rating from BOQ (``PN 16`` → ``PN16``); else null.
  Do not invent a different PN from catalog memory.
- ``make_hint``: only if brand is stated; else null.
- ``attributes``: only keys in ``attribute_keys``. Omit empty keys. Put IS standards in
  ``attributes.is`` when present. Do not put material/body_material in attributes when
  that value belongs in ``class`` for the family; otherwise leave material null.
